# Comparable AI Parser — V1.0.4

## Input format
The parser accepts multi-listing narrative text. Recommended format:

```text
**1. [Judul listing](https://portal.example/iklan/123)**
- Alamat: ...
- Harga: Rp 350.000.000
- LT/LB: 90/60 m2
- Sumber: Portal A

**2. Judul listing berikutnya**
- ...
```

A numbered heading starts one property block. Bullets and paragraphs below it belong to that property until the next sequential numbered heading. Markdown bold and linked titles are supported.

## Output handling
- Gemini returns compact structured JSON using short schema aliases.
- Python expands aliases into the application's full comparable columns.
- URLs are extracted from the user's original text by Python, not generated by Gemini. Google Knowledge Panel URLs containing `kgmid` are excluded from the listing URL field.
- Date found is stamped by the application and is not treated as the listing publication date.
- Missing values remain empty.
- A listing with no building area can still be used for preliminary land-based normalization if land area and price are available; its confidence is penalized.
- If output is cut off (`MAX_TOKENS`) or malformed, the parser rejects the entire response rather than loading partial or misaligned rows.

## Token and request controls
- `max_output_tokens=4096` for each comparable batch.
- Up to four listing blocks per Gemini request when more than five listings are provided; up to five in one request otherwise.
- Larger narratives therefore use multiple requests, still subject to RPM/RPD/TPM quotas for the user's API project.
- The parser enforces a maximum of 10 listings per parse in the Free Tier workflow; split larger sets into separate groups.

## Human review
Always inspect price, LT/LB, source URL, condition, access, listing status and date before using the results for final GO. A portal/category or venue URL may not be an individual listing detail page.
